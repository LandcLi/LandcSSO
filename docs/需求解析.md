一、设计目标

1. 一次登录，多处访问 - 用户只需登录一次即可访问所有信任的应用
2. 安全性 - 防止凭证泄露、会话劫持、CSRF等攻击
3. 可扩展性 - 支持海量用户和高并发
4. 标准化 - 遵循开放协议标准
5. 用户体验 - 减少重复登录，支持多种登录方式

二、核心组件设计

1. 认证中心 (Identity Provider, IdP)

• 统一认证服务 - 处理所有登录请求

• 会话管理 - 维护全局会话状态

• 令牌服务 - 颁发和验证令牌

• 用户目录 - 存储用户身份信息和凭证

2. 服务提供方 (Service Provider, SP)

• 业务应用 - 需要SSO保护的各个系统

• 本地会话 - 维护应用本地会话

• SP客户端SDK - 集成到应用的认证模块

3. 支撑服务

• 会话存储 - Redis集群存储会话数据

• 密钥管理 - 管理签名/加密密钥

• 审计日志 - 记录所有认证事件

• 监控告警 - 实时监控系统状态

三、核心流程设计

1. 首次登录流程


用户访问应用A → 重定向到认证中心 → 用户输入凭证
    ↓
认证中心验证凭证 → 创建全局会话 → 颁发访问令牌
    ↓
重定向回应用A（携带令牌）→ 应用A验证令牌
    ↓
创建本地会话 → 用户访问应用A


2. 访问其他应用流程


用户访问应用B → 应用B检查本地会话（无）
    ↓
重定向到认证中心 → 认证中心检查全局会话（有）
    ↓
直接颁发令牌 → 重定向回应用B
    ↓
应用B验证令牌 → 创建本地会话 → 用户访问


3. 登出流程


用户登出应用A → 通知认证中心
    ↓
认证中心清理全局会话 → 通知所有已登录应用
    ↓
各应用清理本地会话 → 重定向到认证中心登录页


四、安全设计

1. 令牌机制

• 采用JWT格式，包含用户ID、过期时间、颁发者等信息

• 非对称加密签名（RS256），防止伪造

• 短期访问令牌（15-30分钟）+ 长期刷新令牌

• 令牌黑名单处理主动撤销

2. 传输安全

• 强制HTTPS

• 使用State参数防止CSRF攻击

• 使用PKCE（Proof Key for Code Exchange）增强OAuth安全

3. 会话安全

• 会话ID随机生成，高强度加密

• 会话超时机制（可配置）

• 异地登录检测和提醒

• 并发会话数限制

五、协议选择

推荐协议栈：


主协议：OAuth 2.0 + OpenID Connect
    ├── 授权码模式（Web应用）
    ├── 隐式模式（SPA应用，配合PKCE）
    ├── 客户端凭证模式（服务间调用）
    └── 资源所有者密码模式（传统应用迁移期）


标准端点：

• /authorize - 授权端点

• /token - 令牌端点

• /userinfo - 用户信息端点

• /jwks - 公钥端点

• /logout - 登出端点

• /introspect - 令牌验证端点

六、高可用设计

1. 架构层面

• 无状态设计 - 认证中心无状态，依赖外部会话存储

• 水平扩展 - 认证中心可多实例部署

• 多活部署 - 支持跨数据中心部署

2. 数据层

• Redis集群存储会话数据

• 数据库主从/读写分离

• 异地容灾备份

七、用户体验增强

1. 登录方式

• 用户名/密码

• 短信/邮箱验证码

• 第三方登录（微信、钉钉、GitHub等）

• 生物识别

• 扫码登录

2. 无缝体验

• 静默登录（已登录状态下自动认证）

• 记住登录状态

• 设备信任机制

八、监控与运维

1. 监控指标

• 认证成功率/失败率

• 平均认证时长

• 并发会话数

• 令牌颁发频率

• 异常登录检测

2. 审计日志

• 记录所有认证事件

• 存储完整的证据链

• 满足合规性要求
